# PRD — 북키톡키 (강사용 수업 자료 제공 앱)

늘봄(초1-2) 12주 프로그램의 수업 자료를 **강사에게 제공**하는 앱.
요구사항 원본: [북키톡키 콘텐츠 데이터 명세 & 개발 전달 기획 v1.0 (구글 문서, 2026-07-30 확정)](https://docs.google.com/document/d/1BhWqyQ4LN0NkwLunm2Nkjni0ikEFGglsA-kwVKJGPHk/)

이 문서는 확정 명세를 기준으로 **구현 완료 / 부분 구현 / 미착수**를 구분해 관리한다.
(아키텍처 상세는 [SAD.md](./SAD.md), 로컬/원격 스택은 [LOCALSTACK.md](./LOCALSTACK.md)·[REMOTESTACK.md](./REMOTESTACK.md), 콘솔은 [CONSOLE.md](./CONSOLE.md))

## 1. 요구사항 요약 (확정 명세 기준)

- **콘텐츠 구조**: Program(12주) → Week(테마 도서명·한 줄) → Day(일차 1~5, 과목 고정: 책톡/그림톡/소리톡/몸톡/마음톡)
- **Day 구성**: 차시명·수업설명·시간 / steps(도입·활동1~4·마무리) / 준비물(품목·수량) / slides+media(웹 재생) / files(썸네일·수업자료 PDF·지도안 PDF)
- **수업자료 2형태**: ① 웹 "수업 시작" 재생 = 슬라이드 이미지 + 미디어(유튜브 임베드·음악 mp3) ② 다운로드 = PDF
- **지도안**: 다운로드 PDF (화면 비노출, 강사 준비용)
- **파일명 규칙**: `w{주차}d{일차}.png`(썸네일) / `_slide01.png…` / `_lesson.pdf` / `_guide.pdf` / `_audio1.mp3…`
- **핸드오프**: 콘텐츠팀 → 입력 템플릿 엑셀 + 구글 드라이브 폴더. 데이터엔 파일명만(유튜브만 링크 직접 기입). 주차 단위 통째 전달. 서빙은 오브젝트 스토리지+CDN으로 개발이 이관.
- **접근제어**: 로그인한 강사만

## 2. 구현 현황

### ✅ 구현 완료

| 영역 | 내용 | 비고 |
|---|---|---|
| 데이터 모델 (기본) | `weeks`(1~12, 테마·한 줄) / `lessons`(요일 1~5·과목·차시명·설명·시간·썸네일) / `lesson_steps`(순서·단계명·분) / `lesson_preps`(품목·수량) / `materials`(지도안·수업자료 파일) | Drizzle + Postgres(Supabase). 명세의 주차정보·일차정보·수업단계·준비물 시트에 대응 |
| 강사 대시보드 (웹) | 주차 사이드바, 요일 탭, 차시명·설명·수업 흐름·준비물, 썸네일/일러스트, 다른 요일 수업 카드, 1920×1080 시안 재현 | React 19 + TanStack Router/Query + Tailwind v4, bktk.kr 배포 |
| 자료 다운로드 | [지도안 다운받기]·[수업자료 다운받기] → R2 오브젝트를 attachment로 다운로드 | 명세 §6 |
| 파일 서빙 스토리지 | Cloudflare R2(`bktk` 버킷) + Worker `GET /api/files/*` — 명세 §7의 "오브젝트 스토리지+CDN" 결정 사항 이행 | 로컬은 Miniflare 시뮬레이션 |
| 접근제어 | 로그인 강사만 콘텐츠 조회(`requireMember`), 쓰기는 관리자만(`requireAdmin`) | 명세 §10 "접근제어(로그인 강사만)" 결정 이행 |
| 인증 | 이메일 + 카카오 로그인(Supabase Auth), auth.users → users 자동 생성 트리거 | 카카오 앱 "북키톡키" |
| 강사 온보딩 | `schools`/`associations` — 매니저 사전 등록(이메일/전화) → 로그인 시 자동 승인, 복수 학교 소속 시 학교 선택 UI | 명세 외 추가 요구 반영 |
| 관리자 콘솔 | Refine 기반 — 주차/수업(목록·상세·편집)/학교/강사 소속 CRUD, admin_users 뷰로 관리자 검증 | console (5174) |
| 배포 | web=bktk.kr(+www), api=api.bktk.kr(Workers), bktk.co.kr→bktk.kr 301, Supabase 원격(서울) | |

### 🚧 부분 구현 (명세와 차이 있음)

| 영역 | 현재 상태 | 명세와의 차이 |
|---|---|---|
| 수업단계(steps) | 순서·단계명·분 저장 | **단계 유형(도입/활동1~4/마무리) 컬럼 없음** — sortOrder로만 구분 |
| 파일명 규칙 | 데모 데이터가 `w1-mon.png`, `materials/w1/fri/guide.pdf` 형식 | 명세 규칙은 `w{주차}d{일차}` (`w1d1.png`, `w1d1_lesson.pdf`) — 인제스트 구축 시 통일 필요 |
| Day 식별 | `weekday`(1~5) 컬럼 | 명세는 `dayIndex`(스케줄 레이어와 분리 의도) — 의미상 동일하나 명칭·개념 정리 필요 |
| 콘텐츠 데이터 | 1주차 데모 시드만 존재 (수업 40분 기준) | 실제 12주 콘텐츠(80분 수업) 미입력 — 콘텐츠팀 전달물 대기 |

### ❌ 미착수

| 영역 | 명세 근거 | 내용 |
|---|---|---|
| **웹 "수업 시작" 플레이어** | §1, §5 | 슬라이드 이미지 전체화면 순차 렌더, 좌우/키보드 넘김, 미디어 큐 오버레이(유튜브 iframe·오디오 버튼), 슬라이드·음악 사전 캐싱. 현재 "수업 시작" 버튼은 시각 요소일 뿐 |
| slides + media 데이터 모델 | §2, §3-5 | 슬라이드 이미지 목록(장수 파악), 미디어 시트(슬라이드 번호·종류·링크/파일명) 스키마 없음 |
| 음악(mp3)·영상 파일 서빙 | §4 | R2 구조는 준비되어 있으나 모델·업로드·재생 미구현 |
| 입력 템플릿 엑셀 인제스트 | §3, §7 | 북키톡키_콘텐츠_입력템플릿_v5.xlsx → DB 반영 파이프라인 (주차 단위 통째 교체 원칙 포함) |
| 구글 드라이브 → R2 이관 | §7 | 콘텐츠팀 드라이브 폴더의 파일들을 파일명 규칙 검증 후 R2로 옮기는 도구 (현재는 수동 스크립트) |
| PPT → 슬라이드 이미지 변환 | §10 | 수동 export vs 자동 파이프라인 미결정 (명세상 "남은 결정") |
| 검수 체크 자동화 | §9 | 분 합계=시간, 파일명 규칙, 미디어 기입 누락 등 전달물 검증 |

## 3. 다음 단계 (우선순위 제안)

1. **slides/media 스키마 + 웹 플레이어** — 명세의 핵심 미구현 기능. steps 단계 유형 컬럼 추가를 같은 마이그레이션에 포함
2. **엑셀 인제스트 + 파일명 규칙 통일** — 콘텐츠팀 전달물을 받는 즉시 반영 가능한 상태 만들기 (주차 단위 교체, §9 검수 검증 포함)
3. 실 콘텐츠 12주 입력 → 데모 시드 대체
4. PPT 변환 파이프라인 결정 (§10 협의)
